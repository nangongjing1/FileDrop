# Filedrop · 局域网文件传输

一个用 C++ 编写的局域网文件互传工具：

- **服务端**：启动后自动打开浏览器显示控制台；自动发现同一局域网内打开客户端页面的设备。
- **客户端**：手机 / 平板 / 其它电脑用浏览器访问 `http://filedrop.ng/`，即可与服务器互传文件。
- 服务端可以向**一个或多个**设备下发文件，也可以向设备**请求文件**；客户端只能与服务器收发文件，看不到其它设备。

界面为中文，无任何第三方运行时依赖（内嵌 HTTP 服务、DNS 服务与前端资源）。

## 功能

| 服务端 | 客户端 |
| --- | --- |
| 在线设备列表、在线/离线状态与最后在线时间 | 设备名称自定义，身份保存在浏览器本地 |
| 多选设备群发文件，实时显示发送进度 | 拖拽或选择多文件 / 整个文件夹上传，逐文件进度 |
| 从设备接收文件、下载、转发给其它设备 | 接收服务端下发的文件（含大小与 SHA-256） |
| 向指定设备「请求文件」，客户端收到实时提示 | 响应服务器请求，选择文件回传 |
| 设备重命名、传输历史、SHA-256 校验值 | 本次会话的收发记录 |

## 目录结构

```
Makefile                构建脚本（Windows / Linux / macOS）
build.cmd               Windows 快捷构建脚本（自动查找 w64devkit）
src/                    服务端源码（HTTP、SSE、DNS、存储、设备、SHA-256）
web/                    管理端与客户端页面（构建时嵌入可执行文件）
tools/embed_web.py      把 web/ 资源生成 C++ 源文件的脚本
tools/dns_test.cpp      DNS 协议单元测试
```

## 编译

### Windows（MinGW-w64 + GNU make）

需要 `g++` 和 `make`（或 `mingw32-make`）：

```powershell
make            # 生成 filedrop.exe
```

也可以直接运行 `build.cmd`：脚本会自动在常见位置查找 w64devkit，然后调用 `make`。

如果修改了 `web/` 下的页面，需要重新嵌入资源（这一步需要 Python 3）：

```powershell
make assets
make
```

DNS 协议逻辑有独立的单元测试（不依赖网络，可直接运行）：

```powershell
make test-dns
```

> 也可以直接使用 `mingw32-make`。构建产物是静态链接的单个 `filedrop.exe`，正常构建不需要 Python。
>
> 若已安装 Visual Studio 生成工具，也可以在 `vcvars64.bat` 环境中执行 `make MSVC=1`，使用 MSVC 构建。

### Linux / macOS

```bash
make            # 生成 ./filedrop
```

## 运行

```powershell
.\filedrop.exe
```

控制台会打印服务端控制台地址（带一次性随机 token）和客户端地址，并自动打开浏览器。

```
 服务端界面    http://127.0.0.1:80/admin?t=xxxxxxxx
 局域网地址    http://192.168.1.10/
 客户端地址    http://filedrop.ng/
 数据目录      filedrop-data
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--port <端口>` | HTTP 端口，默认 80；80 被占用时自动尝试 8080 |
| `--bind <地址>` | 监听地址，默认 `0.0.0.0` |
| `--data <目录>` | 数据目录，默认 `filedrop-data` |
| `--hostname <域名>` | 客户端域名，默认 `filedrop.ng` |
| `--no-open` | 不自动打开浏览器 |
| `--no-dns` | 不启动内置 DNS |
| `--dns-port <端口>` | DNS 端口，默认 53 |
| `--upstream <IP>` | 上游 DNS，默认读取系统配置 |
| `--keep` | 保留数据目录中的旧文件（默认启动时清空） |

运行中可在控制台输入：

- `s` 查看状态
- `o` 重新打开服务端界面
- `h` 查看帮助
- `q` 退出

## 让局域网设备用 `filedrop.ng` 访问

服务端内置了一个最小 DNS 应答器：对 `filedrop.ng` 返回本机局域网 IP，其它域名转发给上游 DNS，因此设备把 DNS 指向服务端后仍可正常上网。

**方式一（推荐）**：把客户端设备的 DNS 改为控制台显示的局域网 IP。

- Windows：网络设置 → 当前网卡 → IPv4 属性 → 使用下面的 DNS 服务器
- Android：WLAN → 当前网络 → 修改网络 → IP 设置（静态）→ DNS 1
- iOS：WLAN → 当前网络 → 配置 DNS → 手动
- macOS：系统设置 → 网络 → 详情 → DNS

然后访问 `http://filedrop.ng/`（若控制台显示的不是 80 端口，请带上端口，如 `http://filedrop.ng:8080/`）。

**方式二**：修改设备的 hosts 文件，加入一行（IP 以控制台为准）：

```
192.168.1.10 filedrop.ng
```

Windows 的 hosts 位于 `C:\Windows\System32\drivers\etc\hosts`。数据目录中会自动生成 `hosts-help.txt` 和 `clients-hosts.ps1`（在本机以管理员运行）。

**方式三**：不修改 DNS，直接访问控制台显示的 `http://<局域网IP>:<端口>/`。

> 若 DNS 端口 53 被占用（例如系统共享/虚拟网卡服务），内置 DNS 会启动失败并给出提示，此时使用方式二或方式三即可。

## 防火墙

其它设备无法访问时，请以管理员身份放行端口（控制台也会打印）：

```powershell
netsh advfirewall firewall add rule name="Filedrop TCP" dir=in action=allow protocol=TCP localport=80
netsh advfirewall firewall add rule name="Filedrop UDP" dir=in action=allow protocol=UDP localport=53
```

## 使用流程

1. 服务端启动后自动打开控制台，等待设备连接。
2. 客户端打开 `http://filedrop.ng/`，控制台的「已连接设备」中出现该设备（状态点变绿）。
3. **服务端 → 设备**：把文件拖到「待发送文件」，勾选一个或多个设备，点击「发送到已选设备」。客户端收到实时提示，点击「接收」即可保存。
4. **设备 → 服务端**：客户端拖拽文件或文件夹，或点击「选择文件」，文件流式上传到服务端，出现在「已接收文件」中，可下载或转发。
5. **服务端请求文件**：在设备卡片上点击「请求文件」，客户端会出现请求卡片，选择文件后回传。

## 安全与数据

- 服务端控制台使用启动时随机生成的 token 保护，局域网内其它设备无法调用管理接口。
- 客户端使用浏览器本地生成的设备 ID 与密钥，只能读取自己的待接收文件。
- 下发给设备的下载链接为一次性随机令牌，默认 10 分钟内有效且绑定目标设备。
- 客户端页面没有跨设备列表，也不能主动控制服务端。
- 所有文件仅保存在服务端 `filedrop-data/files/`（启动时默认清空，`--keep` 可保留），不经过互联网。
- 协议为明文 HTTP，仅建议在可信局域网内使用。

## 常见问题

**控制台打不开 / 提示需要管理权限**
请使用启动时打印的带 `?t=` 的地址；直接访问 `/admin` 需要有效 Cookie。

**其它设备打不开页面**
检查防火墙；确认客户端与服务端在同一网段；可先用 `http://<IP>:<端口>/` 验证，再排查 DNS。

**客户端收不到文件**
确认设备在线（绿色状态点）且下载链接未过期（10 分钟）；离线设备重新连接后需在有效期内接收。

**大文件上传/下载中断**
传输全程流式处理，不占用大内存；请保持页面打开并避免切换网络。中断后重新发送即可。

**浏览器提示「不安全」**
`http://filedrop.ng` 没有证书，属正常现象，不影响局域网传输。

**`filedrop.exe` 被 Windows 拦截（提示「应用控制策略已阻止此文件」）**
本程序没有数字签名。Windows 11 的 Smart App Control（应用控制策略）默认会拦截未签名程序，这与代码无关。可选处理方式：

- 在「Windows 安全中心 → 应用和浏览器控制 → Smart App Control」中关闭该功能（关闭后需要重置系统才能重新开启）；
- 在未开启 Smart App Control 的电脑或虚拟机上运行；
- 使用受信任的代码签名证书对 `filedrop.exe` 签名后再运行。

**杀毒软件报警**
程序会监听局域网端口并提供浏览器页面，部分安全软件可能对未签名的网络服务报警，请按需加入信任列表。

## 说明

- 服务端仅监听局域网，不主动连接外网。
- 单文件大小仅受磁盘空间限制。
- 传输记录保存在内存中，进程退出即清空。
